# Agent Evaluation & Benchmark Engineering — agent guide

## Overview
12-week course repo. Lessons are markdown; the public site is generated HTML.

## Git (blocking)

**Never push to `main`.** Always branch → PR → merge the PR.

- Do not `git push origin main`, `git push origin HEAD` while on `main`, or fast-forward `main` and push.
- Do not `git merge` into local `main` and push that as a substitute for a PR.
- Create a feature branch, push **that** branch, open a pull request, merge via the PR.

`gh` on this machine is often `dingkwang_tesla` (EMU) and **cannot** create/merge PRs on `dingkwang/agent-eval-course`. Push the branch over SSH as `dingkwang`. Open the PR with a personal GitHub identity, or give the compare URL.

## Key paths
- `PLAN.md` — 12-week map (source of truth for week names)
- `week01/*.md` — lesson source
- `build_site.py` — generates `site/` from those lessons; edit the generator or `.md`, then rebuild
- `site/` — generated HTML (do not hand-edit)
- `labs/` — runnable labs
- `.HANDOFF.md` — untracked session notes; never commit

## Build
```
python3 build_site.py    # from repo root; needs the `markdown` package
```

## Invariants
- Lessons: Chinese. Commits, PRs, code comments: English.
- Relative paths only in markdown.
- `site/*.html` is generated by `build_site.py` — do not edit HTML by hand.

## Known pitfalls
- Default `python3` may lack `markdown`; `/home/dingkwang/looper/.venv/bin/python build_site.py` works on this box.
- `docker exec` is a no-op here; `docker run` in the foreground works.
- Vercel: deploy `site/` with the token in `../vercel-docker/.env`. Do not overwrite the `site` project (that is `llm-rl-course`).
